## Assessment

Claude identified real execution problems: one failed method aborted unrelated methods, there was no invocation timeout, default method lists could request infeasible workloads, pilot failures prevented a useful budget report, and coverage scope errors appeared after expensive loading. Those are repaired below. Its proposed changes to repetitions, motif counting, midpoint sites and job pooling are experimental choices, and several contradict existing instructions or make unsupported scientific assumptions.

**Each core setting has separate jobs.** A 1-core job never includes 4-, 12- or 32-core measurements. Method blocks can be split further within that core setting to fit the allocation. Combining pilot TSVs for a matrix subtotal does not combine their jobs. The existing 24-hour constraint and explicit 1/4-core comparison for the two serial length workloads remain in effect.

No real-input timings, concordance results, Linux installations or Slurm behavior were measured here. Source inspection cannot support Claude's blanket statement that every native command succeeds. Benchmark results remain pending the wiring run and cluster work in [the remaining plan](benchmarks_review_plan.md).

### Scientific invariants checked

- Native commands, pairing definitions, filter masks and timed output work are unchanged by these repairs. The existing directional span vocabulary remains `forward.pos` to `reverse.reference_end`.
- Two warmups and five measurements remain the production defaults. A pilot still has zero warmups and one measurement at its job's single core count. Every explicitly selected method runs unless its own earlier attempt failed.
- A failed invocation contributes no invented successful timing or captured profile. Completed earlier profiles remain usable. Failed/skipped attempts do not enter successful averages.
- Coverage MAE remains the average absolute depth difference over individual bases, including shared zeros. Run lengths are the weights. Pearson is also at 1 bp. No genomic binning was added.
- Residuals remain a histogram by residual value and tool pair, with base counts and fractions. No per-base residual file was added. SQLite stores categories, not a row for every base.
- Sparse omitted zeros are allowed only inside cfDNAlab's declared scope. Dense tracks still require complete native coverage. Explicit `--common-scope` remains necessary for unequal scopes.
- The existing BAM, reference and user-supplied midpoint BED are unchanged. No site generation, subset selection or additional preparation run was introduced.

### Interpretation of doubled left counts

The user accepts side mirroring as a documented approximation for showing similarity. Doubled left counts are therefore an allowed estimated both-end total, while native left counts remain the observed quantity. Multiplying counts by two leaves normalized frequencies unchanged. The approximation's possible error remains relevant: for a hypothetical motif with left count 80/100 and right count 20/100, the measured both-end frequency is 100/200 = 0.5, while doubling the left gives 160/200 = 0.8. This counterexample establishes a limit, not that the discrepancy is large in the intended genome-wide sample. Label the assumption and estimated totals explicitly rather than claiming measured equivalence.

FrEIA also uses aligned read bases and native pairing/deduplication, whereas cfDNAPro `s` motifs use the reference's left boundary after unstranding. Those two one-end quantities need different matching cfDNAlab configurations. Frequency normalization cannot remove read/reference, pairing, selection or end-definition differences.

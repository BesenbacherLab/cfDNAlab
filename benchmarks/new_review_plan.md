## Decisions and current user direction

Decision identifiers match the original review discussion. Settled choices have been implemented and removed from this list.

- **D2: Serial tools and job packing (1.6 and 3).** Decide how to split Griffin's measured repetitions across jobs, pack other methods, and select core settings for the additional motif workloads. The initial separate 1/4-core comparison for cfDNAPro/FinaleToolkit lengths is already specified. Cross-node pooling remains open. Use full-input pilots rather than treating the roughly 30-hour Griffin scenario as a measurement.
- **D4: Midpoint window/normalization and subsets (4).** Discuss window width, normalization and any pilot subsets. The public paper site source is specified. Verify actual file/row counts and the supplied BED's derivation before reporting them. Full-set runtime and memory remain unmeasured.
- **D6: cfDNAPro reference matching and reporting (5).** Native left-end motifs and frequency comparisons are implemented with disclosed side mirroring. Decide final matched configurations and reporting after verifying the bundled BSgenome reference against the alignment FASTA/2bit and measuring native selection differences. Retain the reference manifest and native left counts.
- **D7: Coverage intersection/storage (1.8 and 6).** Discuss automatic intersection versus explicit scope consent. A plain Counter is simpler than SQLite for integer native depths, but changes the current bounded-memory guarantee for accepted fractional tracks. NumPy chromosome arrays change memory/performance requirements. Neither change is necessary to repair fail-fast scope validation.
- **D8: Timeout values and censored observations (1.2, 3 and 4).** Choose per-job run limits after pilots, leaving termination grace and bookkeeping time below the allocation limit. Decide how timeout lower bounds appear in figures and whether one censored run is sufficient. No arbitrary numerical cutoff is installed.
- **D9: Pooling and validation removal (4 and 6).** Pooling separate physical nodes by CPU model, removing physical-placement/reference/BED/version/value checks, or discarding reconstruction provenance are not straightforward bug fixes. The final review will distinguish redundant checks from those preventing invalid scientific comparisons.
- **D10: Documentation layout (6).** Consolidation may help, but deleting the requested specs or moving the plan to `.AI/docs/future/` conflicts with the instruction to keep benchmarks independent. Keep plans and specs in this folder. Discuss any larger consolidation first.
